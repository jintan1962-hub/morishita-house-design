## 1. 報告された2件の原因

### 文字が小さい ── 管理画面だけ Tailwind の寸法が 62.5% で効いていた

`globals.css` の `html { font-size: 62.5% }` は、公開サイトが `1.6rem = 16px` と書くための設定で、
サイト側の設計としては正しい。問題は、管理画面が Tailwind のユーティリティで組まれていたこと。

Tailwind v4 は寸法を全て CSS変数経由で解決する（`.text-sm { font-size: var(--text-sm) }` /
`.h-16 { height: calc(var(--spacing) * 16) }`）。rem は html の font-size が基準なので、
**管理画面の寸法が全て 62.5% に縮んでいた。**ブラウザでの実測値：

| 指定 | 意図 | 実測 |
| :--- | ---: | ---: |
| `text-sm`（サイドバー） | 14px | **8.75px** |
| `text-xs`（表の本文） | 12px | **7.5px** |
| `w-64`（サイドバー幅） | 256px | **160px** |
| `h-16`（ヘッダー高） | 64px | **40px** |
| `p-10`（本文余白） | 40px | **25px** |
| `max-w-lg`（モーダル幅） | 512px | **320px** |

### ログインIDの上が切れる ── 40pxのヘッダーに 45.49px を入れていた

上記でヘッダーが 40px しかない上に、`globals.css` の `p { margin: 0 0 1em }` が管理画面にも効き、
ヘッダー右のIDブロックが下マージン込みで **45.49px** になっていた。`items-center` で中央寄せした結果、
上端が **y = −3.24px**（画面の外）に出て物理的に切れていた。文字サイズの問題と同じ根から出ている。

### 対処

`src/app/(admin)/admin.css` を新設し、管理画面の根要素 `.admin-root` にだけ
**px で書き直した Tailwind のトークン**（`--spacing` / `--text-*` / `--radius-*` / `--container-*`）を載せた。
html の font-size は触っていないため、公開サイトへの影響はない。
あわせてヘッダーを `h-16` から `min-h-16` に変え、中身が増えても切れない構造にした。

修正後の実測：ヘッダー 65px・IDブロック上端 y=14（切れなし）・サイドバー 256px・
サイドバー文字 14px・本文余白 40px。

## 2. 検品で見つかった、報告されていなかった問題

### セキュリティ：会員全員のパスワードハッシュがブラウザへ送られていた

`getUsers` / `getUserById` / `updateUserStatus` が `select` を指定しておらず、Prisma が User の
全列を返していた。`"use server"` の戻り値はそのままブラウザへ配信されるため、`password`（bcryptハッシュ）・
`failedLoginCount`・`lockedUntil`・`deletedBy` が管理画面のレスポンスに載っていた。
`USER_FIELDS` を定義して、画面へ返してよい列だけを明示するようにした（S-01）。

### ダッシュボードが全て架空だった

会員1,284人／物件45件／問い合わせ32件／閲覧12.4k、全カードに根拠のない「+12%」、
「最近の登録会員」は山田健太ら3名、「最近の掲載物件」は仙台の架空物件3件で、
サムネイルは Unsplash の他人の写真を全件同じものを表示していた。

`src/app/actions/dashboard.ts` を新設し、全てDBの実測値に置き換えた。
あわせて、上段に「対応が必要なこと」（未対応の問い合わせ／送信失敗メール／画像0枚の物件）を置き、
件数が0のときだけ「対応が必要なものはありません」を出すようにした。

### 物件一覧のサムネイルが全件同じ他人の写真だった

Unsplash の固定URLを全物件に出していた。管理画面上で物件を取り違える原因になる。
登録済みの1枚目（`PropertyImage.path`）を出し、0枚なら「画像なし」と明示するようにした。

### 公開サイトのフォーム指定が管理画面の入力欄を上書きしていた

`globals.css` の `select, input[type="text"], …, textarea { font-family: 明朝; border-radius: 0; padding: 10px 14px }`
は要素＋属性セレクタのため詳細度が Tailwind より高く、管理画面の `rounded-2xl` `px-4 py-3` `font-gothic` を
全て打ち消していた。`type="search"` だけがこのセレクタから漏れていたため、
**同じ画面の中で入力欄の見た目が食い違っていた。**`.admin-root` 配下を除外して解消。
公開サイト側は変化なし（素の `input[type=text]` が従来どおり 游明朝/15px/余白10px 14px/角0 で描画されることを確認）。

### お問い合わせ一覧の「対応済にする」ボタンが押せなかった

表の親が `overflow-hidden` で、横幅が足りないと「状態 / 詳細」列がスクロールもできずに
切り落とされていた。`overflow-x-auto` を挟み、列幅を詰めて解消。

### `font-gothic` というクラスが存在しなかった

管理画面の全ページに `font-gothic` が書かれていたが定義が無く（`globals.css` にあるのは `.gothic`）、
数字を含む全画面が body の游明朝を継承していた。`.font-gothic` / `.font-mincho` を admin.css に定義し、
地の文はゴシック・見出しは明朝（ブランド）に整理した。

### その他

- 左メニューの選択中表示が「ダッシュボード」に直書きされ、どの画面でも同じ場所が光っていた → URLで判定
- 管理画面からログアウトできなかった（「サイトへ戻る」しか無かった）→ ログアウトを追加
- 会員詳細の「情報を編集する」が何にも繋がっていない一方、実装済みの `updateUserStatus` が
  どこからも呼ばれていなかった → 有効／停止の切り替えとして繋いだ
- 自分自身を削除でき、実行すると管理画面に入れなくなる → `deleteUser` で自己削除を禁止
- 会員詳細の「お気に入り物件」は保持する仕組みがDBに無く常に空 → 撤去
- 「テストデータ作成」は本番では必ず失敗する（O-01の歯止め）→ 開発時のみ表示
- 日本語ラベルへの `uppercase` は無効・`tracking-widest` は字間が開いて読みにくい → 除去
- 詳細モーダルが Esc で閉じられなかった／`role="dialog"` が無かった → 追加
