## 0. 着手前に見つかった事故リスク（先に手当て）

### 0-1. git remote が本家の本番リポジトリを指していた

`origin` が `oonowebpd-cpu/used-housing-site`（8/19に本番稼働中のRENOELサイト）のままだった。
このまま `git push` すると本番サイトのリポジトリを上書きする。

**対処**：`origin` を外し、新しい private リポジトリ
`oonowebpd-cpu/morishita-used-housing-site` を作成して張り替えた。**push はまだしていない。**

### 0-2. `.env` が本家の本番Supabaseを指していた

`.env` の `DATABASE_URL` が本家の `.env` と**ハッシュ一致**（同一の本番接続情報）だった。
`.env.local`（ローカルDocker）が優先されるため普段の開発では当たらないが、
`prisma migrate deploy` や `.env` を読むスクリプトを叩けば本番DBに当たる。

**対処**：`.env` → `.env.renoel-production.bak`、`.env.migrate` → `.env.renoel-migrate.bak` へ退避。
どちらも `.gitignore` の `.env*` の対象でコミットされていないことを確認済み。

**未対応（人間の作業）**：モリシタハウス用の Supabase / Vercel の用意と環境変数の設定（S-01・D-14）。

### 0-3. 他社の計測タグが入ったままだった

公開ページのレイアウトに RENOEL（大井建設工業）の計測IDが直書きされていた
（GA4 `G-8B64PSYP4M` / UA `UA-161807317-6` / Google広告 `AW-951165690` / Yahoo ytag /
Clarity `htt9wpb13p` / Meta Pixel `612628776889149`）。
このまま公開すると**モリシタハウスの訪問者の行動が他社の解析アカウントへ送られる**。

**対処**：`src/config/analytics.ts` ＋ `src/components/Analytics.tsx` に集約し、
IDは全て環境変数からの読み取りにした。**未設定のあいだタグは1本も出力されない。**

## 1. デザインの移植

### 設計方針

| 置き場所 | 中身 |
| :--- | :--- |

## B. ビルドが3回落ちた本当の原因

`.env.example` を Vercel の環境変数一括インポートに貼ったため、
17キーすべてが**「キーだけ・値は空」**で登録されていた。
一覧上は全キーが並ぶので設定済みに見えるが、`NEXTAUTH_SECRET` が空のため
`src/lib/auth.ts` の存在チェックに引っかかり、
`Failed to collect page data for /api/auth/[...nextauth]` でビルドが停止していた。

- Sensitive 指定は無関係（Sensitive でもビルド時には復号される。公式ドキュメントで確認）
- 空値であることは画面からもCLIからも見えない。`vercel env pull` は `"encrypted"` としか返さない
- 入れ直しは削除不要。`vercel env add <KEY> production --force` で上書きできる

再登録は `scripts/setup-vercel-env.sh` に残した。値は一切標準出力に出さない作りで、
`NEXTAUTH_SECRET` は `openssl rand -base64 32` をパイプで直接 Vercel へ渡している
（生成値は人にもAIにも見えていない＝S-01を満たしたまま自動化した）。

環境変数は **Production のみ**に登録した（手順書の初版は Production/Preview 両方）。
Preview に本番DBの接続情報を入れると、ブランチのプレビューが本番DBへ書き込めるため。
