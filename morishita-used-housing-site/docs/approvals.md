## 2026-08-19 メール送信基盤を Resend へ移行（L3）

**変更レベル：L3**（該当理由：外部送信の変更／個人情報（氏名・メール・電話・問い合わせ本文）を
送信するコードの変更／DBスキーマの変更）

**承認の状態：✅ 事前承認あり**
着手前に3案を提示し、大野より次の指示を受けた。
- 実装方式：**案A（fetch で Resend の REST を直接呼ぶ）**
- 作業範囲：送信経路の差し替え／管理者宛通知の追加／送信失敗を気付ける仕組み／ethereal フォールバックの撤去（4項目すべて）
- 送信ドメイン：**未定**。ドメイン認証は後回しにし、まず動くところまで作る

### 着手前に提示した3案

| # | 案 | 利点 | 欠点 | 戻し方 |
|---|---|---|---|---|
| A（採用） | fetch で `https://api.resend.com/emails` を直接呼ぶ | 新規依存ゼロ（S-05に触れない）。送信IDとエラー本文がJSONでそのまま取れる | レスポンス型を自前で定義する必要がある | `git revert` 1コミット（約2分） |
| B | 公式 `resend` SDK を追加 | 型定義つき。将来 React Email 等へ広げやすい | 依存が増え `pnpm audit` の監視対象が増える。前回検品を「新規パッケージ追加0」で通した条件を崩す | revert + `pnpm remove resend`（約5分） |
| C | nodemailer のまま SMTP 先を `smtp.resend.com` に向ける | コード変更ほぼゼロ。`.env` だけで済む | Vercelのサーバーレスでは毎回SMTP接続を張るため遅い。**「黙って失敗する」構造が残る** | `.env` を戻すだけ（約1分） |

案Cを採らなかったのは、今回いちばんの問題が「送信方式」ではなく
**「失敗しても誰も気付かない構造」**だったため。案Cではそこが直らない。

### 着手のきっかけになった事実（調査結果）

`.env` の SMTP 設定はプレースホルダのまま（`SMTP_HOST="smtp.your-server.com"` /
`SMTP_PASS="your-password"`）だった。旧 `mail.ts` は `SMTP_HOST && SMTP_USER` が
あれば本番分岐に入るため ethereal フォールバックにも落ちず、存在しないホストへの接続で例外 →
`catch` で `console.error` → `return false`。呼び出し側は戻り値を見ていない。
**自動返信は一度も届いていなかったが、誰も気付ける状態になかった。**

### D-04（削除・改名）に該当する変更と、その扱い

| 対象 | 扱い | 根拠 |
|---|---|---|
| ethereal テスト送信へのフォールバック | **削除した** | 「未設定のとき送ったつもりになる」経路が今回の事故の原因。大野の承認あり |
| `sendRegistrationEmail` / `sendInquiryEmail` | 関数名・引数はそのまま維持。戻り値のみ `boolean` → `MailResult` へ拡張 | 呼び出し側が失敗を判別できるようにするため。改名はしていない |
| `nodemailer` パッケージ本体 | **削除していない**（未使用のまま残置） | D-04。削除の可否は大野の判断。docs/debt.md に起票済み |
| `SMTP_*` 環境変数 | **削除していない**。`.env.example` に「未使用」と注記のみ | 同上 |

### 判断した設計と、採らなかった案

| # | 論点 | 採用した案 | 採らなかった案 | 採用理由 |
|---|---|---|---|---|
| 1 | APIキー未設定のときの扱い | **失敗として記録する**（開発環境ではコンソールに本文も出す） | 「未設定なら送信しない」を正常扱いにする | 正常扱いにすると、本番で設定を入れ忘れたときに今回と同じ「黙って届かない」状態が再発する |
| 2 | 送信ログに残す情報 | 宛先・件名・状態・失敗理由・Resendのメッセージ IDまで | 本文と入力値も残す | S-09。本文は Inquiry テーブルにあり、二重に持つ意味がない |
| 3 | 送信ログの書き込み失敗 | `try/catch` で握り、本来の受付処理は止めない | 例外を投げて受付ごと失敗させる | 記録できないことを理由に会員登録を失敗させるのは本末転倒 |
| 4 | 本文の置き場所 | `src/lib/mailPayload.ts` に分離（DB非依存の純粋関数） | `mail.ts` に本文と送信を同居させる | DBに繋がずに `node --test` で文面と宛先を検証できるようにするため。テスト7件を追加 |
| 5 | 管理者宛の返信先 | `reply_to` にお客様のアドレスを入れる | 差出人と同じにする | 管理者が受信箱からそのまま返信できるようにするため |
| 6 | 管理者アドレスが未設定のとき | 送らず SKIPPED として記録 | `info@` などを既定値にする | D-03。宛先を推測で埋めると誤送信になる |
